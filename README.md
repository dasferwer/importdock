# ImportDock

Возобновляемый импорт CSV/XLSX в PostgreSQL с сопоставлением колонок, предварительной
проверкой и построчным отчётом. Предметная область ограничена записями
`external_id` и денежной суммой `amount`: глубина проекта — надёжная доставка
большого файла, а не универсальный конструктор таблиц.

## Основные сценарии

- Файл хранится в S3-совместимом хранилище; PostgreSQL хранит состояние задания.
- CSV читается последовательно, XLSX — в режиме `read_only`. Обрабатываются
  порции по 1000 строк. Память не растёт пропорционально числу строк CSV.
- Данные порции, ошибки и контрольная точка фиксируются одной транзакцией.
  При аварийной остановке откатывается только незавершённая порция.
- Сессионная блокировка PostgreSQL не позволяет двум воркерам обрабатывать
  один импорт. После потери соединения блокировка освобождается.
- RabbitMQ уведомляет о заданиях. Воркеры дополнительно опрашивают PostgreSQL:
  сбой публикации или потеря уведомления не теряют задание.
- Повтор того же файла с тем же сопоставлением возвращает прежнее задание.
  Повторный идентификатор внутри файла попадает в ошибки; сохраняется первая строка.
- Частичные данные скрыты из API до завершения. Импорт можно отменить, затем
  удалить его записи через rollback. Отчёт и исходный объект сохраняются.

Стек: Python 3.11+, FastAPI, PostgreSQL 17, RabbitMQ, MinIO/S3, openpyxl, psycopg.
`parser.py` отвечает за чтение и проверку, `worker.py` — за порции и восстановление,
`storage.py` — за S3, `api.py` — за загрузку, просмотр и управление.

## Запуск

```sh
docker compose up --build -d
curl -H 'X-API-Key: local-demo-key' http://localhost:8090/health
printf 'Код,Сумма\na,12.50\nb,ошибка\n' > /tmp/importdock-example.csv
curl http://localhost:8090/imports -H 'X-API-Key: local-demo-key' \
  -F 'file=@/tmp/importdock-example.csv' \
  -F 'mapping={"external_id":"Код","amount":"Сумма"}' -F 'preview=true'
curl http://localhost:8090/imports -H 'X-API-Key: local-demo-key' \
  -F 'file=@/tmp/importdock-example.csv' \
  -F 'mapping={"external_id":"Код","amount":"Сумма"}'
```

Предварительная проверка возвращает первые 20 строк и не создаёт задание.
Замените `<id>` на идентификатор из второго ответа:

```sh
curl -H 'X-API-Key: local-demo-key' http://localhost:8090/imports/<id>
curl -H 'X-API-Key: local-demo-key' http://localhost:8090/imports/<id>/errors
curl -H 'X-API-Key: local-demo-key' http://localhost:8090/imports/<id>/records
curl -X POST -H 'X-API-Key: local-demo-key' http://localhost:8090/imports/<id>/cancel
curl -X POST -H 'X-API-Key: local-demo-key' http://localhost:8090/imports/<id>/rollback
```

Для записей `after` — последний `external_id`, для ошибок — номер последней
строки данных, начиная с 1 без заголовка. `limit` ограничен 1000.
Схема API: `/docs`. Неверный ключ — 401, некорректный файл — 422,
недоступное хранилище — 503, просмотр незавершённых данных — 409.

## Тесты и аварийный сценарий

Нужны `uv` и Docker:

```sh
cp .env.example .env
set -a
. ./.env
set +a
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
uv run python -m scripts.recovery
```

Тесты используют временные схемы БД. Сценарий recovery создаёт миллион строк,
останавливает только воркер этого Compose-проекта через SIGKILL после сохранения
первых порций, запускает его снова и сверяет количество и сумму записей.
Ожидается 1 000 000 строк, 0 ошибок, сумма 1 250 000,00. Скрипт требует работающий
Compose-стенд и оставляет импорт для просмотра. Можно задать `ROWS=10000`.
CI выполняет тесты и полный сценарий восстановления.

## Ограничения

CSV: UTF-8, запятая, уникальная строка заголовков. XLSX: только активный лист,
формулы не вычисляются; формула в сумме считается ошибкой. Не более 512 МиБ
файла и распакованного XLSX. Файл скачивается на временный диск целиком; нужна
свободная дисковая ёмкость. XLSX может использовать память для общих строк,
поэтому постоянный расход памяти гарантируется только для обычного CSV
с ограниченным размером строки. CSV ограничен стандартным `csv.field_size_limit`.

CSV сохраняет байтовую позицию после полной логической записи в одной транзакции
с данными, ошибками и номером строки. При восстановлении разбирается заголовок,
затем выполняется seek к позиции; префикс повторно не разбирается. Это работает
с UTF-8, BOM, LF/CRLF и переводами строк внутри кавычек. Физическая строка ограничена
1 МиБ, логическая запись — 2 МиБ; отдельное поле также ограничивает csv.
XLSX и старые задания без байтовой позиции по-прежнему перечитываются до контрольной точки. Импорты изолированы по заданию; нет объединения
в общий каталог и многопользовательских прав. До обращения к S3 фиксируется задание со статусом `uploading` и SHA-256.
При отказе оно становится `upload_failed`; повтор идентичной загрузки продолжает
тот же процесс. После аварийного завершения в `uploading` также требуется повторная
загрузка клиентом. Объект всегда имеет запись-владельца; автоматической очистки
завершённых и неудачных заданий всё ещё нет. Старые бесхозные объекты не удаляются.
После отмены повторная загрузка возвращает то же задание. Для явного продолжения
используйте `POST /imports/{id}/resume`: доступны `cancelled` и `failed`, но не
`rolled_back`. Продолжение сохраняет подтверждённые строки и checkpoint.
Перед обработкой воркер сверяет SHA-256 всего скачанного объекта. Поэтому полный
файл по-прежнему скачивается и читается для проверки целостности; ускоряется
именно разбор CSV, а не сетевой перенос или вычисление хеша.
Демо-пароли и API-ключ подходят только для локального стенда; порты привязаны
к localhost. Остановка: `docker compose down`, данные в томах сохраняются.
